## Global Constraints (from the spec §3 — non-negotiable, gate against these)
1. **Server is the money authority.** The client NEVER computes/displays a self-derived discount total; the review total is ALWAYS the server quote's number. Client eligibility checks only show/hide the affordance.
2. **Redeem requires a verified non-guest `customer_uid`** (server-verified token uid, `customer:true`, tombstone-checked — never a client-supplied uid). **Guest checkout byte-identical to today** (no `body.redeem`, no path change).
3. **Display surfaces (chip, pane, cart-earn) are read-only `user_rewards` (read-own) and FLAG-INDEPENDENT** — render whenever a logged-in customer has a balance.
4. **The redeem affordance renders ONLY when redemption is live for this customer** — `config/rewards_public/redemption_live === true` OR this customer's read-own `user_rewards/{uid}/{rid}/canary === true`. Never a "coming soon" control that can't complete.
5. **No half-baked/crammed UI.** Every state (loading/error/unavailable/ineligible) is clean per the mockup, or it isn't shown. Owner aesthetic: no cramming, perfect alignment — verify before/after each screen.
6. **Byte-identical past `CONFIG`** across the two brands; **guest byte-identical** to today. Brand differences (punch-card vs points/tiers, copy, palette, glyph) live ONLY in the `CONFIG` block.
7. **The rules addition is RTDB-emulator-verified** (leaf-only read cascade; JSON/codex miss RTDB cascade semantics). `redemptionEnabled` keeps strict `=== true` / fail-safe-OFF.
8. **Deploy owner-gated:** functions BEFORE forms; the go-live flip is a SINGLE ATOMIC multi-location write (`redemption_enabled` + `rewards_public/redemption_live` together); rollback is the same write in reverse.
9. **No change to B1 money-path logic** (reserve/consume/reversal/sweeps) — B2 is UI + activation only. Exports no-prune (46 → **47**, the one new `quoteRedemption`).

## Task 1: Backend activation — `quoteRedemption` endpoint + `redemptionEnabled(db, uid)` allowlist + call-site reorder  [MONEY-GATE]
**Files:** `rewards-redeem-config.js` · `rewards-redeem-intake.js` · `index.js` (new export) · tests.

**Interfaces — Produces:** `redemptionEnabled(db, uid)`; `quoteRedemption` HTTPS fn.

- [ ] **Step 1 — `redemptionEnabled(db, uid)` allowlist (additive, back-compatible).** Extend to: `config/redemption_enabled === true` **OR** (`uid` given AND `config/redemption_allowlist/${uid} === true`). Read global first, allowlist second; keep strict `=== true`; **fail-closed OFF on any read error**; `uid` absent ⇒ global-flag-only (back-compat for any other caller). Unit test: global-true→true; global-false + allowlisted-uid→true; global-false + non-allowlisted→false; global-false + no-uid→false; read-throw→false; non-boolean allowlist value→false.
- [ ] **Step 2 — call-site reorder (uid-first) in `prepareRedemption`.** It currently calls `redemptionEnabled(db)` BEFORE `customerUid` is validated. Reorder: validate the verified non-guest `customerUid` FIRST (return `login_required` if absent), THEN `redemptionEnabled(db, customerUid)`. This flows to BOTH intake paths (cash `resolveRedemptionForOrder`, online `chargeOnlineOrder`) since both go through `prepareRedemption`. **Confirm in-build:** the reorder must not change the guest/flag-off outcome ordering in a way that alters the typed error a client already depends on — a flag-OFF *guest* now returns `login_required` (uid-first) instead of `rewards_disabled`; both are non-payable 409/401 and the guest never sends `redeem`, so this is inert, but assert it explicitly. Extend the intake emulator test: allowlisted-uid + global-OFF → the reserve proceeds; non-allowlisted + global-OFF → 409 `rewards_disabled`.
- [ ] **Step 3 — `quoteRedemption` read-only endpoint (§5.1).** New `onRequest` HTTPS fn. Input: `body.items`, `body.redeem`, `restaurant_id`, header `X-Firebase-ID-Token`. Flow, reusing the EXACT intake code so quote==submit by construction: (a) resolve `restaurant_id`; (b) verify the token → non-guest `customerUid` (same verify+tombstone as intake; absent → 401 `login_required`); (c) **`computeServerTotal(body.items, restaurantId)`** server-side (never trust a client total); (d) **`prepareRedemption(db, { redeem, items, restaurantId, itemsText:'', totalLempiras: total, customerUid })`** — the SAME gate+compute+avail(86)+price the intake runs, NO reserve; on `!ok` return its typed error verbatim; (e) **read-only available check**: read `user_rewards/{uid}/{rid}` → `available = (balance||0) − (reserved||0)`; if `available < redemption.cost` → return `{ ok:false, status:409, error:'redemption_reserve_failed', reason:'insufficient' }` (mirrors the reserve's rejection); (f) success → `{ ok:true, discount_cents, total_cents, subtotal_cents, tax_cents, free_item:{ name } }` from `priced` (`free_item.name` = sanitized client display name for La Musa / the server `free_item_key` for X. Pizza). **NO reserve, NO order, NO DB write, NO side effects.** CORS as the other customer endpoints; fail-safe (any throw → typed 500, never a partial).
- [ ] **Step 4 — no-prune + export count.** `grep -cE "^exports\." index.js` → **47** (exactly +1 `quoteRedemption`, all 46 prior present). `node --check` all touched. Emulator: `quoteRedemption` returns the discounted numbers for a valid xp/lm redeem (allowlisted or flag-on), the SAME typed errors as intake for each failure (flag-off non-allowlisted → `rewards_disabled`; guest → `login_required`; 86'd lm item → `reward_unavailable`; below-balance → `insufficient`), and takes NO reserve (assert `user_rewards.reserved` unchanged + no `reservations/{orderId}`). **Assert quote==submit:** a passing quote's `total_cents` equals the total the intake charges for the same cart+redeem (drive both, compare). **Commit** — `feat(rewards-b2): quoteRedemption read-only endpoint + redemptionEnabled(db,uid) allowlist`.

## Task 4: Checkout redemption — affordance + quote review + submit + typed-409 + fresh-resubmit fallback  [MONEY-TOUCHING UI]
**Files:** BOTH forms (`index.html` checkout + `account.js` helpers), byte-identical past `CONFIG`.
- [ ] **Step 1 — the affordance (screen 4), gated.** Render ONLY when `redemption_live === true` OR read-own `canary === true`, AND the customer is eligible (X. Pizza `available ≥ card_size` AND ≥1 server-priceable pizza in cart; La Musa `available ≥ min offered tier.cost`). X. Pizza: single **"Usar"** → pending `redeem = {}`. La Musa: **tier picker** offering only affordable tiers and only currently-available (not-86'd) items (so the server never has to reject). Never show a control that can't complete (Constraint #4).
- [ ] **Step 2 — quote + review (screen 5).** On reward select, call `quoteRedemption` (§5.1) → render the struck-through discount line + the new total FROM THE SERVER QUOTE (never client-computed). X. Pizza: cheapest pizza struck, total drops by its base unit. La Musa: added item "GRATIS", total unchanged. Quote failure → the typed message, don't offer the reward.
- [ ] **Step 3 — submit + response handling.** On order submit, send `body.redeem` + the token (request shape otherwise unchanged); the server recomputes authoritatively + charges the discounted total. Typed-409/401 → clean message (map `reward_unavailable`→"Ese premio no está disponible ahora" + drop the item; `login_required`→prompt login; `redemption_invalid`/`_pricing_failed`/`_reserve_failed` incl `insufficient`→"No pudimos aplicar el premio, intentá de nuevo"; `rewards_disabled`→hide the affordance). **Fresh-resubmit fallback (Constraint, spec §5.2):** on ANY redeem failure the client clears the pending `redeem`, shows the message, and lets the customer re-submit **full-price with a fresh/regenerated `order_id` identity** (NEVER reuse the failed submit's id). "Continuar sin premio" = this clean fresh full-price submit.
- [ ] **Step 4 — edge states (spec §8), each clean:** lm 86'd mid-flow → drop+re-pick; server-freed item ≠ client guess → server total wins; balance changed → graceful clear → full price; cart changed after select → re-send selection / clear if now invalid (e.g. last pizza removed). **Guest path unchanged** (no affordance, no `body.redeem`). **Commit** — `feat(rewards-b2): checkout redeem affordance + quote review + submit + typed-409 + fresh-resubmit fallback`.
